# Management Center 2.0 / VideoHub 2.1 升级

## 备份并分别覆盖各自项目源码

这次必须同时升级 Management_Center 和所有需要参与中央资源分发的 VideoHub 节点。不要用新项目覆盖或删除现有 `.env`、`data/`、`backups/`、`logs/`。保持原 `MC_MASTER_KEY`（站点凭据的加密根密钥），否则旧记录无法解密。先分别运行旧版备份命令，离线保留备份。维护窗口内停服务后更新源码，重新构建镜像；已有 SQLite 数据启动时自动迁移。

```bash
# 两个项目分别在各自服务器执行（旧版 docker-compose 兼容）
docker-compose up -d --build --force-recreate
# 或 bash start.sh
```

正式环境默认 `MC_SECURE_COOKIE=1`、`MC_ALLOW_HTTP_LOCAL=0`；可信局域网 HTTP 测试 `MC_SECURE_COOKIE=0`、`MC_ALLOW_HTTP_LOCAL=1`、`MC_BIND=0.0.0.0`，VideoHub `VIDEOHUB_BIND=0.0.0.0`。本版已包含 RFC1918 内网 HTTP 补丁，禁止明文公网 HTTP，不改变签名验证。测试环境仍要求容器能访问目标服务器；Colima 虚拟网络故障不是应用能修复的。

## 操作

登录后进入白色全宽仪表板。左侧站点管理可添加、编辑、检测、解绑站点。顶栏选择一个或全部站点；需要指定站点的分类/标签/广告等页面要求先选单站。中央视频库填写标题、远程封面、网络视频地址、多条线路、分类、标签、授权信息后保存或分发。可勾选视频批量操作。发布、同步、冻结、解冻、回收站、恢复分别由持久队列执行，并在每站点独立数据库记录状态。解冻或恢复不会自动发布。任务中心可重试同一分发版本；遇到源链接与既有独立视频冲突时不会自动吞并，应人工处理远端记录。原站点已有视频可在站点视频菜单直接编辑、发布、下架、添加线路，暂不会自动归入中央库。

仪表板采集使用健康任务缓存，通过“采集站点数据”或任务中心定时 health 调度刷新。浏览量为 VideoHub 视频页去重计数，不能视为全站 PV、真实播放、UV 或广告收益。广告收益尚未对接，显示空值。所有运营任务仍在管理中心执行。高级项目（联盟收入、站点模板、分组、中央/站点覆盖、自动分发规则、自动旧视频接管、冲突对账、全站 UV/渠道归因、永久删除与中央版本回滚）未在本版完成。

API 认证、CSRF 和 HMAC 仍保留；生产请通过 HTTPS、必要时限制管理 API 访问源。原会话或密钥如果曾在对话中暴露，按安全流程轮换。不要未经迁移直接更换已使用的主加密密钥。
